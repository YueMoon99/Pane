## 2. 里程碑详解

### M0 · 环境与脚手架

**目标**：一行命令能构建出空白原生窗口。

| 任务 | 说明 |
|---|---|
| 安装/切换 Xcode 26 | `sudo xcode-select -s /Applications/Xcode.app/...` |
| 创建工程 | Xcode 项目（App，SwiftUI lifecycle，macOS 15.0 deployment target）或 SwiftPM |
| 目录骨架 | 按 `02-架构设计.md §9` 建立分组（可先为空文件占位） |
| Design Tokens | `UI/Design/Tokens.swift`：间距、字号、圆角、行高常量 |
| 构建脚本 | `Scripts/build.sh`、`Scripts/benchmark.sh` 骨架 |
| Git | `.gitignore`（Xcode 模板） |

**验收**：`⌘R` 或脚本运行后，出现一个遵循系统外观的空白窗口，标题栏与 Tahoe 风格一致。

---

### M1 · 静态 UI 原型 ★ 先确认「好看」

**目标**：不接文件系统，先把界面长相定死。

| 任务 | 说明 |
|---|---|
| 窗口骨架 | `NavigationSplitView` + unified toolbar |
| 侧边栏 | 4 个分组，硬编码示例数据，含服务器状态灯 |
| 工具栏 | 后退/前进/视图切换/操作菜单/搜索/显示/设置 |
| 路径栏 | 面包屑（示例路径，可点击） |
| 内容区 | 三种分栏布局切换（示例文件网格） |
| 状态栏 | 项目数 / 选中大小 / 剩余空间 |
| 外观切换 | 跟随系统 / 浅色 / 深色（即时生效） |
| 空状态 | 空文件夹 / 无权限 / 加载骨架 |

**验收（视觉走查 12 项）**：
1. 侧边栏材质与系统设置.app 一致
2. 深色模式无硬编码亮色残留
3. 工具栏图标为 SF Symbols 且大小统一
4. 选中行圆角 6pt，失焦状态可区分
5. 行高与间距符合 §2.1 数值
6. 分栏切换动画自然无跳变
7. 路径栏长路径折叠正确
8. 状态栏数字右对齐、有千分位
9. 窗口缩放至最小尺寸不破版
10. 系统强调色变更后 UI 跟随
11. 「减弱透明度」下仍可读
12. 与访达并排截图对比，观感无明显违和

### M2 · 文件系统接入

**目标**：能真正浏览、导航、实时刷新。

| 任务 | 说明 |
|---|---|
| `FileItem` 模型 | 8 项属性一次预取 |
| `DirectoryLoader` | actor，异步枚举 + 分批产出（首批 500） |
| `DirectoryModel` | `@Observable`，加载态/错误态 |
| **虚拟化列表引擎** | `FileListView`（AppKit），cell 复用，60fps |
| 列表视图渲染器 | 多列：名称/大小/种类/日期/标签 |
| 选择系统 | ⌃/⇧/⌘/框选/全选/反选/首字母跳转/方向键 |
| `NavigationHistory` | 每 Pane 独立后退/前进栈 |
| `DirectoryWatcher` | FSEvents，200ms debounce，增量 diff |
| `IconService` | `NSWorkspace.icon` + LRU |
| 打开行为 | 默认打开 / ⌘双击新窗口 / ⌥双击简介（修饰键先占位，M5 补全逻辑） |

**验收**：
- 打开含 10,000 项目的目录，首屏 < 200ms，滚动满帧
- 外部创建/删除文件后 200ms 内自动反映
- 选择、框选、连选行为与访达一致
- 内存 < 250MB

## 5. 已确认决策（Xcode 安装期间冻结）

> 状态：用户已拍板，开工即按此执行，无需再问。

| # | 决策项 | 结论 |
|---|---|---|
| **Q1** | 产品名 + Bundle ID | **`Pane`** · `com.moon.pane` |
| **Q2** | 是否安装 Xcode 26 | **安装中**。装好后用 Xcode 26 构建（带预览/Instruments）；在此之前不写代码 |
| **Q3** | 最低系统版本 | **macOS 26.0（Tahoe）**。因此可**直接**使用 Liquid Glass、`glassEffect` 等 macOS 26 新 API，无需 `#available` 分支，代码更简洁 |

| **Q8** | 终端 | **仅 Terminal（系统自带）**。但 `TerminalService` 做成可扩展：未来可自动检测 iTerm2 / Warp / Ghostty 并加入列表，默认 Terminal |

## 6. 开工后的第一步

决策确认后，我的执行顺序：

1. **创建工程骨架** + `Design Tokens`
2. **M1 静态 UI 原型**（先用 SwiftUI 把「好看」这件事落地，跑起来给你看）
3. 你确认观感后，再进入 M2 真实文件系统接入（此时会引入 AppKit 虚拟化引擎）

这样安排的原因：**先锁死外观，再投入重工程**——避免把虚拟化引擎写完才发现视觉方向不对，返工成本极高。
