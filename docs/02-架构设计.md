# 架构设计

> 项目工作代号：**Pane**
> 平台：macOS 15.0+ / Apple Silicon / Swift 6 / SwiftUI + AppKit 混合
> 文档版本：v1.0

---

## 1. 设计原则

| # | 原则 | 说明 |
|---|---|---|
| P1 | **系统控件优先** | 能复用 AppKit/SwiftUI 原生控件就不自绘。外观交给系统，我们只负责组合与布局 |
| P2 | **虚拟化一切长列表** | 任何可能超过 200 项的列表都必须虚拟化 |
| P3 | **UI 永不阻塞** | 任何 I/O（枚举、stat、缩略图、哈希、复制）一律异步，主线程只做渲染 |
| P4 | **单向数据流** | 用户动作 → `AppCommand` → Handler → 状态变更 → 视图刷新。禁止视图直接改模型 |
| P5 | **后端可替换** | 本地/SMB/未来 SFTP 统一 `FileSystemProvider` 协议，上层无感知 |
| P6 | **操作可撤销、可中断** | 所有破坏性操作走 `FileOperationEngine`，带状态机、进度、回滚 |
| P7 | **零第三方依赖** | 只用系统框架（见 01 文档 §4.3） |
| P8 | **特性优先于层级** | 目录按 Feature 划分，避免 `Views/Models/ViewModels` 大杂烩 |

## 2. 分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  L4  UI 层                                                      │
│  SwiftUI: 窗口 / 侧边栏 / 工具栏 / 路径栏 / 设置 / 弹窗 / 检视器   │
│  AppKit(桥接): FileListView 引擎 / NSMenu / QLPreviewPanel / DnD │
│  职责：渲染、捕获输入、派发 AppCommand                            │
└─────────────────────────────────────────────────────────────────┘
                              ↓ AppCommand
┌─────────────────────────────────────────────────────────────────┐
│  L3  编排层（Coordination）                                      │
│  CommandBus · WindowManager · PaneCoordinator · NavigationHistory│
│  SelectionManager · ClipboardManager · TaskCenter                │
│  职责：把命令翻译成一次或多次领域操作，管理窗口/栏位/标签页状态     │
└─────────────────────────────────────────────────────────────────┘
                              ↓ Domain Call
┌─────────────────────────────────────────────────────────────────┐
│  L2  领域层（Domain）                                            │
│  FileSystemProvider(协议) · LocalProvider · SMBProvider           │
│  VolumeRegistry · DirectoryModel · FileItem · Operation 状态机    │
│  职责：文件系统语义、路径规则、冲突规则、排序规则（不含 UI）        │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  L1  服务层（Services）                                          │
│  IconService · ThumbnailService · MetadataService · Watcher       │
│  ArchiveService · HashService · TerminalService · QuickLook       │
│  KeychainService · ServerStore · BookmarkStore · SettingsStore    │
│  职责：无状态能力提供者，可被任意层调用，内部自带缓存              │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  L0  系统                                                        │
│  FileManager · FSEvents · NetFS · Security · QuickLook            │
│  CryptoKit · libarchive · CoreServices · AppKit · SwiftUI         │
└─────────────────────────────────────────────────────────────────┘
```

**依赖方向严格自上而下**，L1 服务层不知道 UI 存在，L2 领域层不知道命令总线存在。这样单元测试可以在无 UI 环境下跑全部领域逻辑。

## 4. 核心接口契约

> 以下为**架构契约**（接口签名），用于锁定各层边界，非实现代码。

### 4.1 文件系统抽象（最重要）

```swift
// L2 领域层
protocol FileSystemProvider: Sendable {
    var id: VolumeID { get }
    var kind: VolumeKind { get }          // .local  .smb  .archive(未来)
    var isWritable: Bool { get }

    func contents(of url: URL, options: ListingOptions) async throws -> [FileItem]
    func attributes(of url: URL) async throws -> FileAttributes

    func createDirectory(at url: URL) async throws
    func copy(from src: URL, to dst: URL, reporter: ProgressReporter?) async throws
    func move(from src: URL, to dst: URL, reporter: ProgressReporter?) async throws
    func trash(_ urls: [URL]) async throws -> [URL]        // 返回实际废纸篓位置
    func delete(_ urls: [URL], reporter: ProgressReporter?) async throws
    func setAttributes(_ attrs: FileAttributes, of url: URL) async throws
}

// 监听器：目录变更 → 增量更新
protocol FileSystemObservable {
    func observe(_ url: URL) -> AsyncStream<DirectoryChange>
}
```

`SMBProvider` 的实现策略：挂载成功后，返回的 URL 就是本地挂载点路径，内部直接委托给 `LocalProvider`。因此 **SMB 只影响「挂载/卸载/重连」三个动作，不影响文件读写代码路径**。

服务器的「共享列表」是一个**虚拟位置**：`PaneModel.url` 用合成标识 `smb://host` 表示它（不是文件 URL），`load()` 见到该 scheme 就改走 `ServerModel.ensureSession` 拿共享清单，并把每个共享映射成 `FileItem(kind: .share, isShare: true)`。双击共享才 `SMBMounter.mountShare` 挂到 `/Volumes/共享名` 并 `navigate` 过去；位置标识随历史栈与标签页快照一起持久化，所以「重启后回到上次的服务器列表」不需要额外状态。这类条目没有本地路径，因此文件类命令（拷贝/删除/压缩/新建…）用 `CommandContext.isServerRoot` 统一置灰。

### 4.2 命令系统

```swift
// L3：所有用户动作的唯一入口，菜单项/快捷键/工具栏/右键菜单全部绑定到这里
enum AppCommand: Hashable {
    // 导航
    case open(OpenMode)                    // .default  .newTab  .newWindow  .inspector
    case goBack, goForward, goUp, goTo(URL)
    // 选择
    case selectAll, deselectAll, invertSelection
    // 剪贴板
    case copyItems, cutItems, paste(PasteMode), copyPath(PathFormat)
    case duplicate
    // 文件操作
    case trash, delete, rename, compress(ArchiveFormat), makeAlias
    case newFolder, newFile(FileTemplate), computeHash(HashAlgorithm)
    case showInspector, quickLook, openWith(URL?), share
    // 视图
    case setViewMode(ViewMode)             // .icon  .list  .column  .gallery
    case setPaneLayout(PaneLayout)         // .single  .horizontal  .vertical
    case focusPane(PaneSlot)               // .primary  .secondary
    case copyToOtherPane, moveToOtherPane, syncOtherPane
    case toggleHiddenFiles, toggleSidebar, togglePathBar, toggleStatusBar
    case showViewOptions
    // 服务器
    case connectServer(ServerID?), disconnectServer(ServerID), connectToServerSheet
    // 搜索 / 窗口 / 应用
    case search(scope: SearchScope), newTab, closeTab, newWindow
    case quickJump, showSettings, showBatchRename
}
```

**命令总线的四个职责**：
1. **单一事实来源**：同一个动作（比如「移到废纸篓」）被右键菜单、快捷键 ⌘⌫、工具栏按钮触发时，走完全相同的代码路径，启用/禁用状态自动同步
2. **上下文感知**：`canExecute(command, context) -> Bool`，根据当前选中项、当前 Pane、卷可写性自动禁用无效项
3. **快捷键可定制**：命令 ID ↔ 快捷键映射存在 `SettingsStore`，偏好设置里可视化录制
4. **可测试**：领域逻辑可脱离 UI 直接调用命令验证

### 4.4 文件操作引擎

```swift
final class FileOperationEngine {
    func enqueue(_ op: FileOperation) -> OperationHandle
}

struct FileOperation {
    let kind: Kind                      // .copy .move .trash .delete .rename .compress .extract
    let sources: [URL]
    let destination: URL?
    let conflictPolicy: ConflictPolicy // .ask .skip .replace .keepBoth .keepNewer
    var state: OperationState          // .pending .preparing .running .paused .completed .cancelled .failed
}

struct OperationHandle {
    func pause() / resume() / cancel()
    var progress: AsyncStream<ProgressReport>     // 已传输/总数/速度/剩余时间
}
```

## 5. 状态与数据流

### 5.1 单向数据流

```
 ┌────────┐   用户动作    ┌──────────┐   领域调用   ┌─────────────┐
 │  View  │ ───────────▶ │CommandBus│ ──────────▶ │  Domain /    │
 │        │              │          │             │  Services    │
 └────────┘              └──────────┘             └─────────────┘
     ▲                                                    │
     │            @Observable 状态变更                     │
     └────────────────────────────────────────────────────┘
                     （主线程合并，批量刷新）
```

### 5.2 状态归属

| 状态 | 持有者 | 生命周期 |
|---|---|---|
| `AppState` | App 级 `@Observable` | 应用级（设置、外观、服务器列表） |
| `WindowState` | 每窗口 | 窗口级（标签页集合、分栏布局、窗口尺寸） |
| `TabState` | 每标签页 | 标签页级（各 Pane 的路径与视图状态） |
| `PaneState` | 每 Pane | Pane 级（历史、排序、视图模式、选择、滚动） |
| `DirectoryModel` | 每 Pane 当前目录 | 目录级（条目、加载态） |

**关键设计**：Pane 状态与目录内容分离。切换标签页/分栏布局时，`PaneState` 保留（路径、历史、排序、视图模式不丢），只重新挂载视图。

### 5.3 刷新节流

目录变更事件（FSEvents）可能每秒数十次。策略：

```
FSEvents 原始事件 → 200ms debounce → 合并为 diff（新增/删除/改名/属性变）
                → 主线程 apply（无动画，除非只有 1–2 项变化才动画）
                → 保留选择集（按 url 而非 index）
                → 保留滚动位置
```

## 6. 并发模型

| 任务类型 | 机制 | 说明 |
|---|---|---|
| 目录枚举 | `actor DirectoryLoader` + `Task.detached` | 后台优先级 `.userInitiated` |
| 图标/缩略图 | `Task` + `TaskGroup`（上限 8 并发） | 优先级 `.utility`，可取消 |
| 文件复制/移动 | `DispatchIO` + `OperationQueue`（串行，maxConcurrent=1 默认） | 同一目标卷串行，跨卷可并行 |
| 哈希 | `TaskGroup`，并发数 = `ProcessInfo.activeProcessorCount` | 大文件流式，不占内存 |
| 目录大小统计 | 后台递归 `Task` | 增量更新 UI（显示 `≈` 前缀） |
| UI 状态更新 | `@MainActor` | 所有可观察状态变更走主线程 |
| 网络状态 | `NWPathMonitor` | 独立队列 |

**Swift 6 严格并发**带来的好处：所有跨线程共享的可变状态在编译期就会被标记，从根源上消灭「文件列表偶发崩溃/错乱」这类最难排查的问题。

## 7. 缓存策略

| 缓存 | 层级 | 容量/失效 |
|---|---|---|
| 文件图标 | 内存 LRU | 2000 条；卷卸载时清 |
| 缩略图 | 内存 LRU → 磁盘（`~/Library/Caches/Pane/thumbs/`） | 内存 300 张；磁盘 500MB，LRU 淘汰 |
| 目录列表 | 内存（短时） | 60s TTL 或目录变更即失效 |
| 目录大小 | 内存 + 持久化（可选） | 目录变更即失效 |
| 文件元数据（尺寸/时长） | 内存 LRU | 1000 条 |

缩略图 key = `url.path + 尺寸档位 + 文件 mtime`，避免过期图。

**网络卷（SMB / AFP / NFS）上的缩略图默认不生成**：一张缩略图就是一次完整文件读取，一屏几十个 cell 同时请求会把带宽吃满。判断依据是 `VolumeInspector.isLocal`（读 `volumeIsLocal`，按卷缓存）。设置里可以打开「在网络宗卷上显示缩略图」（`thumbs.remote`）：打开后只对图片 / 视频 / PDF 生成，图片与 PDF 限 64MB，视频不限体积（QuickLook 只取首帧），并走独立的限流闸门（并发 2，本机为 4）；生成结果照样落磁盘缓存，第二次进同一目录直接命中。切换开关会清空内存缓存并让格子重新请求。

### 8.3 安全

- 密码**只存 Keychain**，永不写入 JSON / UserDefaults / 日志
- 书签使用 security-scoped bookmark，启动时 `startAccessingSecurityScopedResource()`
- 所有 shell 调用（终端、unar）做完整路径转义，防注入
- 日志文件脱敏（不记录完整凭证 URL）

## 10. 性能预算与度量

| 指标 | 目标 | 度量方式 |
|---|---|---|
| 冷启动到窗口可见 | < 400ms | `signpost` + Instruments |
| 10k 项首屏 | < 200ms | 基准测试脚本 |
| 100k 项首屏 | < 800ms | 基准测试脚本 |
| 滚动帧率 | 60fps（掉帧 < 1%） | Instruments Animation Hitches |
| 常规内存 | < 250MB | Instruments Allocations |
| 目录切换（缓存命中） | < 100ms | signpost |
| 主线程阻塞 | 单次 < 16ms | 主线程卡顿监控（DEBUG 断言） |

**门禁**：M3 之后，每次大改需跑 `Scripts/benchmark.sh`（自动生成 1k/10k/50k 文件目录）并附结果。

## 11. 可测试性设计

| 层 | 测试方式 |
|---|---|
| L2 领域 | 纯 Swift 单元测试，`MockProvider` 提供内存文件系统，无需真实磁盘 |
| L3 编排 | 命令 → 断言状态变更；可注入 Mock 引擎 |
| L1 服务 | 针对真实小样本的集成测试（哈希已知值、归档往返） |
| L4 UI | XCUITest 覆盖：新建窗口 → 切换分栏 → 导航 → 复制 → 废纸篓 → 撤销 |

`MockProvider` 的存在是 P5 原则的直接收益——90% 的领域逻辑可以在毫秒级测试套件中验证，不依赖真实文件系统。
