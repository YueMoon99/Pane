# 可行性分析与技术选型

> 项目工作代号：**Pane**（最终产品名待定，见 §9 待决策清单）
> 目标平台：macOS 15.0+（针对 macOS 26 Tahoe 优化）／ Apple Silicon
> 文档版本：v1.0　日期：2026-10-29

---

## 1. 结论摘要

**结论：技术上完全可行，且能达到「UI 与原生融合 + 易用性不低于访达」的目标。**

三条决定成败的关键决策（详见 §4、§5）：

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | UI 技术栈 | **SwiftUI 为主 + AppKit 承接性能关键路径**（混合架构） | 纯 SwiftUI 撑不住大目录（>5000 项）滚动；纯 AppKit 开发效率低、易写出「不原生」的自绘控件。混合方案让 90% 界面自动获得 Tahoe/Liquid Glass 外观，10% 热点用 AppKit 换取 60fps |
| D2 | SMB 实现 | **一期 NetFS 系统挂载，二期可选 AMSMB2 直连**，两者统一在 VFS 抽象层之后 | NetFS 免费、稳、系统级缓存与 Spotlight 可用、速度最优；AMSMB2 支持多凭证并发但性能略低且为 LGPL |
| D3 | 沙盒 | **不启用 App Sandbox** | 访达级能力（任意路径访问、SMB 挂载到 /Volumes、调用终端与外部工具）在沙盒下处处受限。代价是不上 Mac App Store，改用 Developer ID 签名 + 公证（或本地 ad-hoc 签名） |

风险等级：**中低**。最大风险不在「能不能做」，而在「大目录性能」与「文件操作可靠性」，均已有成熟工程解法（§5.2、§5.3），且可在 M2/M3 里程碑用基准测试量化验证。

### 2.1 关于「QSpace Pro 里可复用的东西」

已核查两处，结论如下：

**① 工作区内没有 QSpace Pro 文件夹** —— `WorkBuddy WorkSpace` 下只有 `BlenderBatchRendererWeb`、`resource-monitor`、`WorkBuddy_QQ` 三个项目，全库搜索 `QSpace|Qspace|qspace` 零命中。

| 资源 | 内容 | 能否复用 |
|---|---|---|
| `Assets.car` | 编译后的资源目录（图标/图片） | ❌ 第三方版权资产，复制即侵权 |

| `Frameworks/` | AMSMB2、Alamofire、CryptoSwift、KeychainSwift、SnapKit、ShortcutRecorder 等 | ⚠️ 框架本身是开源库，但**应自行从 SwiftPM 引入官方版本**，不要搬运它链接的副本（版本陈旧、签名不符） |

**可合法复用的是「产品理念」，我已把它提炼为设计输入**（§6 竞品对标）。其中有 3 个来自 QSpace 的杀手级特性值得直接纳入一期：
- **跨栏拖拽**（⌥ 拖动=移动，⌘⌥=替身）——双栏文件管理的核心价值
- **工作区（Workspace）记忆**——保存一组分栏布局+路径，一键恢复
- **左右栏同步操作**（复制到对侧 / 移动到对侧 / 对侧同步导航）

## 3. 需求拆解与达标路径

对照你提出的四条最低要求，逐条给出实现路径与难度评级（★越多越难）。

| 你的要求 | 实现路径 | 难度 |
|---|---|---|
| **① 分栏：单栏 / 横向切分 / 纵向切分** | 自研 `PaneContainer`：`NSSplitViewController` 承载 1–2 个 `PaneView`，布局枚举 `single / horizontal / vertical`；每 Pane 独立持有路径历史、视图模式、排序、选择、滚动位置 | ★★☆ |
| **② 左侧书签 + 服务器** | `NavigationSplitView` + `List(selection:)` 构建分组侧边栏；书签用 security-scoped bookmark 持久化；服务器项显示连接状态灯 | ★★☆ |
| **③ SMB 连接** | `NetFSMountURLAsync` 挂载到 `/Volumes/AppName-Server-Share`；凭证存 Keychain；`NWPathMonitor` + `NSWorkspace` 挂载通知实现自动重连 | ★★★ |
| **④ 三种外观** | 跟随系统 → `NSApp.appearance = nil`；浅色 → `.aqua`；深色 → `.darkAqua`。全程只用语义色，不写死任何颜色值 | ★☆☆ |
| **⑤ 设置里填服务器，显示在主界面左侧** | `ServerStore`（JSON，仅存元数据）+ `KeychainStore`（仅存密码），设置页与侧边栏共享同一 `@Observable` | ★★☆ |
| **⑥ 右键菜单（文件 / 空白处，分组+细横线）** | `NSMenu` 原生构建（SwiftUI 的 `.contextMenu` 无法画分隔组、无法做子菜单图标），每个菜单项绑定 `AppCommand` | ★★☆ |
| **⑦ 修饰键双击（⌥=简介，⌘=新窗口）** | 子类化列表视图拦截 `mouseDown` 的 `clickCount == 2` + `modifierFlags` | ★☆☆ |
| **⑧ ⌘⌫ 移到废纸篓等快捷键** | 统一命令总线 + `ShortcutRecorder` 风格的可定制键盘偏好设置 | ★★☆ |
| **⑨ 访达基础功能照搬（空格预览、四种视图、框选、⌃多选、⇧连选）** | QuickLook 共享面板 + 自研虚拟化列表引擎（含 marquee 框选） | ★★★★ |

**唯一的 ★★★★ 是第 ⑨ 项**——因为「空格预览、框选、⌃多选、⇧连选」这些访达行为，SwiftUI 的 `List` 全部不支持，必须自研基于 AppKit 的虚拟化列表引擎。这也正是 D1 决策（混合架构）的由来。好消息是：这个引擎一旦做好，四种视图模式（图标/列表/列视图/画廊）可以复用同一套虚拟化 + 选择 + 键盘导航逻辑。

## 4. 技术选型对比

### 4.1 三个候选方案

| 维度 | A. 纯 SwiftUI | B. 纯 AppKit | C. Tauri / Electron |
|---|---|---|---|
| 与 macOS 26 外观融合 | ⭐⭐⭐⭐⭐ 自动获得 Liquid Glass | ⭐⭐⭐ 需手工配置材质 | ⭐ 网页控件，一眼假 |
| 大目录（1万+项）性能 | ⭐⭐ `List` 会卡顿 | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| 右键菜单 / 快捷键控制力 | ⭐⭐ 受限 | ⭐⭐⭐⭐⭐ 完全控制 | ⭐⭐ |
| 开发效率 | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| 内存占用 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐（Electron 300MB+） |
| QuickLook / 系统服务集成 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| **综合** | 界面满分，核心功能不及格 | 能力满分，效率偏低 | 第一要务直接失守 |

**C 方案一票否决**：你的第一要务是「好看」= 与苹果原生完美相融。Electron/Tauri 自绘的滚动条、菜单、选中态在 macOS 26 的 Liquid Glass 下会非常违和，且内存与启动速度都不像一个系统级工具。

### 4.2 推荐：A + B 混合（按界面区域划分）

```
┌──────────────────────────────────────────────────────────┐
│ SwiftUI 负责（自动获得原生外观，开发快）                  │
│  • 窗口 / NavigationSplitView / 侧边栏 List              │
│  • 工具栏、路径栏面包屑、状态栏                           │
│  • 偏好设置、所有弹窗与 Sheet                             │
│  • 检视器 / 简介窗口                                      │
├──────────────────────────────────────────────────────────┤
│ AppKit 负责（性能与系统行为，NSViewRepresentable 桥接）   │
│  • FileListView：虚拟化列表引擎（1:N 复用 cell）          │
│    ├ 图标视图  NSCollectionView + 自定义 layout           │
│    ├ 列表视图  NSTableView（.inset / 交替行）             │
│    ├ 列视图    自研多列 NSTableView 级联                  │
│    └ 画廊视图  NSCollectionView + 大预览                  │
│  • 框选（marquee）、⌃多选、⇧连选、键盘导航                │
│  • NSMenu 右键菜单（原生分隔组 + 子菜单）                 │
│  • QLPreviewPanel（空格预览，共享面板）                   │
│  • Drag & Drop（含跨 Pane、跨 App）                       │
└──────────────────────────────────────────────────────────┘
```

**核心原则：能不自定义就不自定义。** 侧边栏用 `.navigationSplitView`，按钮用 `.bordered` / `.borderless` + SF Symbols，颜色只用语义色（`.labelColor`、`.secondaryLabelColor`、`.controlAccentColor`），材质用 `.sidebar` / `.windowBackground`。这样系统在 26 上给玻璃效果、在 15 上给 vibrancy，我们一行适配代码都不用写。

**部署目标设为 macOS 15.0**（覆盖绝大多数 M 系机器），macOS 26 专属增强用 `#available(macOS 26, *)` 分支渐进启用。

## 5. 关键能力可行性深挖

### 5.1 SMB 连接（★ 最高技术风险）

两条路线的正式对比：

| 维度 | NetFS 系统挂载（推荐一期） | AMSMB2 协议直连（二期可选） |
|---|---|---|
| 实现方式 | `NetFSMountURLAsync(smbURL, mountAtDir, user, pass, ...)` | 库内直接实现 SMB2/3 读写 |
| 速度 | ⭐⭐⭐⭐⭐ 内核级缓存 | ⭐⭐⭐⭐ 用户态，约 80–90% |
| 多凭证并发 | ❌ 同一服务器只能一套凭证（系统限制） | ✅ 可并存 |
| 其他 App 可见 | ✅ 挂载后全系统可见 | ❌ 仅本 App |
| Spotlight / 时间机器 | ✅ | ❌ |
| 权限要求 | 普通用户即可（访达同款路径） | 无 |
| 断线恢复 | 需自己监听 + 重挂 | 库内重连 |
| 许可 | 系统框架，无负担 | **LGPL-2.1**（分发有合规义务） |
| 工作量 | 小（≈ 300 行） | 大（需重写全部文件操作后端） |

**一期实现要点：**

```text
1) 连接流程
   设置/⌘K 输入 → 构造 smb://user[:pass]@host[:port]/share
   → Keychain 查/存凭证 → NetFSMountURLAsync(kNetFSMountAtMountDirKey: /Volumes/Pane-<别名>)
   → 成功写入 recentServers + 侧边栏状态 → 失败区分：认证失败 / 主机不可达 / 共享不存在 / 已挂载

2) 状态机
   disconnected → connecting → mounted → (网络中断) → reconnecting → mounted | failed
   侧边栏对应显示：灰点 / 转圈 / 绿点 / 黄点

3) 监控
   • NSWorkspace.didMountNotification / didUnmountNotification / didRenameVolumeNotification
   • NWPathMonitor 监听网络可达性
   • 后台 5s 心跳 stat 挂载点（检测静默断线）

4) 断开
   优先 unmount("/Volumes/...", MNT_FORCE)，失败降级 diskutil unmount / unmount force
```

**架构保障**：无论底层是 NetFS 还是 AMSMB2，上层只看到 `FileSystemProvider` 协议（`list / attributes / copy / move / remove / createDirectory / rename`），二期切换零成本。**这是本项目最重要的一个抽象。**

### 5.2 文件列表性能（★ 次高工程风险）

**目标指标（M 系机器）：**

| 场景 | 目标 |
|---|---|
| 10,000 项目录首次渲染 | < 200ms |
| 100,000 项目录首次渲染 | < 800ms（分批 500 条增量渲染） |
| 滚动帧率 | 稳定 60fps（掉帧 < 1%） |
| 快速拖动滚动条 | 无白屏（占位骨架） |
| 常规使用内存 | < 250MB |
| 目录切换响应 | < 100ms（含缓存命中） |

**达成手段：**

1. **虚拟化**：只创建可视区域 + 2 屏缓冲的 cell，10 万项目录实际 cell 数量 ≈ 60 个
2. **异步枚举**：`FileManager.enumerator` + `batchParameters` 走 `contentsOfDirectory(includingPropertiesForKeys:)`，一次性批量预取 `name/size/date/type/isDirectory/isPackage` 共 8 个属性，避免逐项 stat（此项通常带来 3–5 倍提速）
3. **增量渲染**：前 500 项立即渲染，其余后台分批插入，配合 `NSDiffableDataSource` 的 `apply(_:animatingDifferences: false)`
4. **排序下沉**：排序在后台 actor 完成，主线程只消费结果
5. **图标三级缓存**：内存 LRU（2000 条）→ 磁盘缓存目录 → `QLThumbnailGenerator` 生成；滚动中暂停缩略图请求，停止 100ms 后批量补
6. **任务取消**：目录切换时 `Task.cancel()`，所有在飞的图标/元数据请求立刻作废

### 5.3 文件操作可靠性（★ 数据安全的生命线）

`FileManager.copyItem` 不满足需求（无进度、无冲突处理、无取消）。自研 `FileOperationEngine`：

```
状态机：pending → preparing(冲突预检) → running → (paused) → completed
                                     ↘ cancelled(回滚) ↘ failed(部分完成提示)

特性：
• 分块读写 4MB，DispatchIO 异步；>100MB 文件显示速度/剩余时间
• 同卷移动用 rename()（原子、瞬时）；跨卷自动降级为 copy+delete
• 冲突策略：询问 / 跳过 / 替换 / 保留两者 / 仅保留较新
• 取消：删除已写入的部分文件，保证不留垃圾
• 重试：网络卷 ENOTCONN/ETIMEDOUT 自动退避重试 3 次
• 校验：可选「复制后比对大小 + 首末 1MB 哈希」
• 撤销栈：⌘Z 可撤销移动/重命名/删除
• 原子写：临时名 .pane-tmp-xxx → 完成后 rename，避免半成品被其他 App 读到
• 权限：保留 POSIX 权限、扩展属性（xattr）、Finder 标签
```

**UI 配套**：底部统一任务面板（类似访达的拷贝进度，但支持多任务、暂停/继续、折叠为小浮窗）。

### 5.4 原生外观（Tahoe / Liquid Glass）

| 元素 | 做法 |
|---|---|
| 窗口 | `NSWindow.styleMask` 含 `.fullSizeContentView`；`toolbarStyle = .unified`（Tahoe 自动大标题+玻璃工具栏） |
| 侧边栏 | SwiftUI `NavigationSplitView` sidebar；macOS 26 自动渲染为玻璃圆角容器 |
| 材质 | `.background(.regularMaterial)` / `NSVisualEffectView(.sidebar)`；**不手写 blur** |
| 颜色 | 100% 语义色 + `Color(nsColor:)`，零硬编码 hex |
| 图标 | SF Symbols 为主（macOS 26 的 SF Symbols 7）+ 文件类型走 `NSWorkspace.icon(forFile:)`（自动获得原生文档图标） |
| 强调色 | 跟随系统 `controlAccentColor`，不强制自定义 |
| 动态 | 自动响应系统外观切换、强调色变更、字号变更 |

### 5.5 沙盒与权限（关键取舍）

**决策：不启用 App Sandbox。** 需要的能力与沙盒冲突如下：

| 能力 | 沙盒下的问题 |
|---|---|
| 访问任意路径 | 需逐个用户授权，访达级体验不可实现 |
| SMB 挂载到 /Volumes | 沙盒禁止写入 /Volumes |
| 在终端打开当前目录 | 需 `com.apple.security.files.user-selected.executable` + 用户选中，体验割裂 |
| 调用 unar / Keka 解压 | 受 outbound/inbound entitlements 限制 |

**代价与应对：**
- 无法上架 Mac App Store → 采用 Developer ID 签名 + Apple 公证（notarization）后 DMG 分发；个人自用可直接 ad-hoc / 自签证书签名
- 首次访问受保护目录（桌面/文稿/下载/外接盘）仍需用户在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」中授权 → 首启引导页会检测并给出一键跳转链接

| 计算哈希 | CryptoKit 流式，多文件并行，结果可复制/导出 CSV | ✅ |
| 压缩 | libarchive（zip / tar.gz） | ✅ |
| Finder 标签 | `NSURLTagNamesKey` + ` NSURLLabelNumberKey` | ✅ |
| 列视图（分栏模式） | 自研多列级联 `NSTableView`，非 `NSBrowser`（控制力更强） | ✅ |

## 6. 竞品对标与差异化

### 6.1 QSpace Pro 功能地图（据其资源推断）

从 `Frameworks/` 与 nib 命名可反推其产品结构：

- **核心**：双栏/多栏布局（`JHSSpaceIconsView` / `SpaceColumnsListView` / `SpaceGroupListView`）、布局选择器（`JHSLayoutPickerViewController`）
- **特色**：工作区记忆（`JHSWorkspaceChooseController`）、文件夹同步/对比（`JHSFolderSyncFiltersController`、`icon_sync_copy_to_right` 等）
- **工具**：批量重命名（`JHSBatchRenameLiteWindowController` + 预设/日志）、压缩（`JHSCompressWindowController`）、文件检视器（`JHSFileInspectorController`）、标签（`JHSTagViewController`）、评论（`JHSCommentViewController`）、任务列表（`JHSTaskListWindowController`）、进程控制台
- **云**：阿里云盘、百度网盘、Dropbox、Box、OneDrive、Google Drive、七牛、又拍云、腾讯 COS、AWS S3（大量 `icon_*.tiff` 与 `*_AuthController.nib`）
- **存储栈**：`AMSMB2`（SMB）、`swift-nio`（网络）、`swift-crypto`（加密）、`Alamofire`（HTTP）

### 6.2 我们的策略：「窄而深」

不追云盘生态（那是 QSpace 的重资产区），而是把 **本地 + SMB 双栏场景做到极致**：

| 维度 | 访达 | QSpace Pro | **Pane（我们）** |
|---|---|---|---|
| 原生外观 | 满分（本身就是） | 良好（有自绘痕迹） | **满分（全系统控件 + 语义色）** |
| 双栏效率 | ❌ 无双栏 | ✅ | ✅ **且跨栏拖拽手感更细** |
| 分栏模式 | 仅标签页 | 多布局 | ✅ 单栏/横切/纵切 + 标签页 + 工作区 |
| 批量重命名 | ❌ 系统级弱 | ✅ | ✅ 一期内置，含正则/序号/预览 |
| 哈希计算 | ❌ | ✅ | ✅ |
| 终端集成 | ❌（需服务） | ✅ | ✅ |
| 云盘 | ❌ | ✅✅ 广泛 | ❌（不做） |
| 内存占用 | 中 | 中 | **低（原生 + 0 依赖）** |
| 启动速度 | 快 | 中 | **快（冷启 < 400ms 目标）** |

### 6.3 差异化亮点（超出你最低要求、但建议纳入的部分）

1. **智能跨栏操作**：选中后 `⌃⌘→` 复制到对侧 / `⌃⌘⇧→` 移动到对侧；`⌥` 拖拽=移动，`⌘⌥`=替身
2. **工作区（Workspace）**：保存「分栏布局 + 各栏路径 + 视图模式」快照，⌃1–9 快速切换（⌘1–3 留给切分模式）；开机自动恢复上次工作区
3. **快速跳转（⌘⇧J）**：模糊搜索书签/最近目录/服务器，Enter 直达（Raycast 风格）
4. **目录大小异步计算**：⌘J 勾选「计算所有大小」后后台递归统计，配合侧栏迷你图
5. **剪贴板历史（近期复制路径）**：⌘⇧V 弹出最近 10 条复制/剪切记录
6. **批量操作中心**：批量重命名、批量改权限、批量哈希、批量压缩，统一入口
7. **双栏对比色**：激活栏有细微强调（2px accent 顶边），避免误操作

## 8. 开发与构建方案

### 8.1 推荐：安装 Xcode（强烈建议）

你的当前环境只有 Command Line Tools，**可以命令行编译 SwiftUI App，但没有预览、没有 Instruments、没有 Asset Catalog 编辑器**。以「好看」为第一要务，视觉迭代效率至关重要。

```bash
# 安装 Xcode 命令行工具完整版（若先装 Xcode.app，则会自动提供）
xcode-select --install          # 已装
# 建议从 App Store 安装 Xcode 26，然后：
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
```

### 8.2 备选：纯命令行（无 Xcode）

完全可行，我已在你的环境验证 Swift 6.4 可用。路线：

```
SwiftPM Package（App target 用 swift-tools-version:6.0）
  ├ Sources/PaneApp/*.swift          # @main App、Views、Services
  ├ Sources/PaneApp/Resources/       # 资源（需手工 bundle）
  └ Scripts/build.sh                 # swift build -c release
                                     → 组装 Pane.app/Contents/{MacOS,Resources,Info.plist}
                                     → codesign --force --deep --sign -
                                     → open Pane.app
```

缺点：改一个 padding 要重新编译（约 10–40s），无法所见即所得。**建议仅作为 CI/兜底方案。**

### 8.3 工程约定

- 最低部署：macOS 15.0；SDK：macOS 26；Swift 6 language mode（严格并发）
- 代码组织：按特性（Feature）分目录，而非按层级（View/Model/ViewModel）
- 无第三方依赖（见 §4.3）
- 所有用户可见字符串走 `Localizable.xcstrings`（中文为主，英文为辅）
