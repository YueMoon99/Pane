# Pane · 前期设计总览

> macOS 原生文件管理器 · 工作代号 **Pane**（产品名待定）
> 目标：**UI 与苹果原生完美相融**，易用性高于访达，追赶 QSpace Pro
> 环境实测：macOS 26.6.2 Tahoe / arm64 / Swift 6.4 / Xcode 未安装
> 版本 v1.0 · 2026-10-29

---

## 一句话结论

**可行。** 用 **SwiftUI（外观） + AppKit（性能关键路径）** 混合架构、**NetFS 系统挂载** 实现 SMB、**不启用沙盒** 换取访达级能力，可以在约 **30 人日**内交付一个外观与原生无异、双栏效率超越访达的文件管理器。

---

## 三条核心决策

| # | 决策 | 为什么 |
|---|---|---|
| **D1** | **SwiftUI 为主 + AppKit 承接热点** | 90% 界面用系统控件 → 自动获得 Tahoe / Liquid Glass 外观，一行适配代码都不用写；文件列表等 10% 热点用 AppKit 换取 60fps 与访达级交互（框选/⌃多选/⇧连选/空格预览） |
| **D2** | **SMB 一期走 NetFS 系统挂载** | 免费、内核级缓存速度最优、Spotlight 可用、其他 App 也能访问；统一在 `FileSystemProvider` 协议之后，二期可无缝换 AMSMB2 直连 |
| **D3** | **不启用 App Sandbox** | 任意路径访问、挂载到 /Volumes、调用终端与外部工具——这些在沙盒下处处受限。代价是不上 Mac App Store，改用 Developer ID 公证或本地自签 |

**最重要的架构抽象**：`FileSystemProvider` 协议。上层所有代码（列表、复制、删除、拖拽）只认这个协议，本地磁盘、SMB、未来的 SFTP 只是不同实现。这让 SMB 的复杂度被隔离在一个 300 行的模块里。

## 关于 QSpace Pro 可复用资源

已核查：

1. **工作区内没有 QSpace Pro 文件夹** —— 全库搜索零命中
2. **`/Applications/QSpace Pro.app` 的资源不可复用**：
   - `Assets.car`（图标）、40+ 个 `.nib`（编译界面）、13 种 `.lproj`（文案）均为**第三方版权资产**
   - `Frameworks/` 里的 AMSMB2、Alamofire、CryptoSwift 等是开源库，但**应自行从 SwiftPM 引入官方版本**，不搬运它链接的旧副本

**可合法复用的是产品理念**，我已提炼并纳入设计：
- 跨栏拖拽（⌥ 移动 / ⌘⌥ 替身）
- 工作区（Workspace）记忆
- 双栏同步操作

我们的策略是「**窄而深**」：不做云盘生态（QSpace 的重资产区），把**本地 + SMB 双栏场景**做到极致，并用「全系统控件 + 零硬编码颜色」把「好看」做到比 QSpace 更彻底。
